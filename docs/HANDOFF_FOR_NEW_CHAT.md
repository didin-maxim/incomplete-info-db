Это файловая база задач про неполную информацию: взвешивания, мудрецы, общие
знания, карточные фокусы, вопросы с ложью и доказательства невозможности.

## Источник истины

Главный источник истины - `data/`.

Особенно важны:

- `data/problems/` - карточки задач и лемм
- `data/relations/` - межкарточные связи
- `data/sources/` - источники
- `data/definitions/` - определения
- `data/standard_ideas/` - повторяемые идеи стратегий
- `data/taxonomy/` - фрагменты, теги, статусы, типы связей
- `data/comments/` - комментарии ревьюеров

Производные артефакты:

- `viewer/index.html`
- `docs/index.html`, если скопирован viewer для публикации
- `index/generated.sqlite`

Для интерактивов сначала смотрите `docs/INTERACTIVE_ENGINE_GUIDE.md`: там карта
движков, YAML-полей, selftest и типовых ловушек.

## После обрыва или сжатия контекста

Сначала восстанавливайте состояние из файлов, а не из памяти чата:

```powershell
git status --short
python tools\check_encoding.py
python tools\validate.py
```

Если агент упал, посмотрите, остались ли частичные изменения в его зоне работы,
и запускайте следующего агента "по следам" с конкретным списком файлов/id.
Длинные проходы должны оставлять устойчивый след в `docs/reviews/`,
`data/import_batches/`, карточках или relation-файлах.

## Что важно не ломать

1. Не редактировать viewer и SQLite как источник истины.
2. Не класть неполную стратегию в `strategies[]`.
3. Для оптимальных задач фиксировать не только стратегию, но и нижнюю оценку.
4. Для взвешиваний заполнять `weighing_profile`.
5. Для вопросов с ложью заполнять `questions_profile`.
6. Добавлять связи только при общем информационном механизме.
7. Не выдавать `mailto`, копирование отчета, GitHub issue без backend или `localStorage` за запись комментария в базу. Если комментарий должен попадать в `data/comments/` без регистрации пользователя, нужен deployed backend endpoint по `docs/FEEDBACK_ENDPOINT.md`; без него это технический blocker статического GitHub Pages.
8. По комментариям и другим внешним интеграциям различать "подготовлено" и "работает". Агент имеет право отчитаться об успехе только после живой проверки полного пути: frontend отправил запрос, backend с секретом принял его и создал запись/PR/issue в согласованном месте. Если endpoint не развернут или проверка шла только на mock-сервере, финальный статус: "не готово к пользовательскому использованию", с точной причиной.

## Стартовый корпус

В первой версии добавлены 8 карточек:

- 12 монет за 3 взвешивания
- 9 монет за 2 взвешивания

- грязные дети и общее знание
- заготовка для трех мудрецов со шляпами
- фокус Чейни с пятью картами
- бинарное угадывание числа
- нижняя оценка для вопросов с одной ложью

Главная следующая работа - расширять корпус и уточнять фрагментные профили на
реальных олимпиадных задачах.
