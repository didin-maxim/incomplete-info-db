# Полевая карта агента

Короткий справочник для агента, который продолжает работу после сжатия контекста, обрыва связи или чужого незавершенного прохода.

## 1. Сначала восстановить состояние

```powershell
git status --short
python tools\check_encoding.py
python tools\validate.py
```

Не считайте summary чата источником истины. Источник истины - файлы в репозитории и текущий diff. Если в дереве уже есть чужие изменения, не откатывайте их и не форматируйте рядом без необходимости.

## 2. Где что лежит

- `data/problems/` - карточки задач. Работайте только с нужными id и соседними карточками по теме.
- `data/relations/relations.d/` - связи между карточками. Добавляйте связь только при общем информационном механизме, а не при похожем сюжете.
- `data/import_batches/` - очереди и следы импортов по источникам. Перед новым импортом проверьте, не лежит ли задача уже в batch.
- `data/sources/sources.yaml` - источники и авторы источников.
- `data/taxonomy/` - допустимые fragments, tags, statuses, difficulty, relation types.
- `data/comments/` - замечания ревьюеров; открытые удобно смотреть через `python tools\comments.py --status open`.
- `docs/reviews/` - устойчивые рабочие списки и отчеты агентов. Это главное место для очередей после долгих проходов.
- `viewer/index.html`, `docs/index.html`, `index.html`, `index/generated.sqlite` - производные артефакты; вручную не лечить.

## 3. Очереди и быстрый поиск

- Публичная готовность: `rg -n "public_ready: false|review_status: needs_human_review|needs_human_review" data/problems docs/reviews`.
- Карточки с интерактивами: `rg -n "^interactive:|type:" data/problems`.
- Очередь интерактивов: `docs/reviews/interactive-status.md` и `docs/reviews/interactive-next-candidates.md`. Если параллельный агент ведет интерактивы, не меняйте эти файлы и не трогайте код viewer без явного задания.
- Кластерные обзоры: `docs/reviews/cluster-*.md` и `data/navigation/`.
- Дубли перед добавлением: ищите по источнику, числам и ключевым словам: `python tools\search.py query "12 монет 3 взвешивания"` и `rg -n "source_id|12|три взвеш" data/problems data/import_batches`.

## 4. Маркеры качества

Если человек указал на одну явную ошибку, считайте ее скрытым маркером класса ошибок. Не исправляйте только найденную карточку: сначала сформулируйте общий критерий, затем проверьте похожие карточки, batch и relations.

Для карточки, которую нельзя довести до `public_ready`, оставьте конкретную причину в `editorial.notes`: нужен рисунок, не доказана нижняя оценка, источник не сверен, стратегия неполная, есть риск дубля.

## 5. Что проверять в карточке

- `statements.original` самодостаточен, без служебного языка и английских хвостов.
- Заголовки, короткие идеи, `difficulty.comment` и навигационные описания звучат
  по-школьному: сначала обычное название вроде `Что все знают после фразы вслух`,
  а технические слова (`сигнатуры`, `канал`, `пространство состояний`) только там,
  где без них действительно нельзя.
- Модель информации закрыта: из условия ясно, кто что видит, что помнит, какие
  сообщения публичные, где запрещены частные подсказки и лишние наблюдения.
  Если возможен обход через память/наблюдение/лишний канал, не ставьте
  `public_ready` до уточнения.
- `ideas`, `strategies`, `impossibility_proofs` не смешивают условие и решение; неполная стратегия не должна выглядеть готовой.
- `difficulty.comment` объясняет трудность конкретно, без слова "стандартная" как заглушки.
- Для взвешиваний есть `weighing_profile`; для вопросов с ложью - `questions_profile`; для карточных фокусов - `card_trick_profile`.
- `sources[].source_id` существует, страницы/заметки указаны настолько точно, насколько позволяет источник.
- `authors` - это авторы задачи или источника, а не агент, который импортировал карточку.
- `interactive` описывает модель и параметры, но не оптимальное первое действие, таблицу решения или стратегию.

## 6. Минимальные проверки перед финалом

```powershell
python tools\check_encoding.py
python tools\validate.py
python tools\check_links.py
python tools\audit_rules.py
```

Если менялись только docs, минимум - `python tools\check_encoding.py`. Если менялись `tools/`, правила схемы, YAML карточек или relations, запускайте `validate.py` и `audit_rules.py`; предупреждения audit либо исправьте, либо объясните в финале.

## 7. Шаблон финального отчета агента

В конце долгого прохода оставьте отчет, который можно продолжить без истории чата:

- Проверено: id карточек, batch-файлы, review-файлы или диапазон источника.
- Изменено: конкретные файлы и кратко что в них.
- Не тронуто намеренно: чужие незавершенные зоны, generated HTML, интерактивные движки, если они вне задания.
- Осталось: нерешенные id, риски дублей, источники без сверки, audit warnings.
- Проверки: точные команды и результат.

Для интеграций с внешним миром добавляйте отдельную строку "Работает ли у пользователя". Если нет развернутого endpoint, секрета, доступа к API или живой проверки записи, пишите "не работает до ..." и называйте blocker. Нельзя маскировать незавершенную работу словами "реализовано" или "готово": frontend-кнопка, mock-сервер, документация или шаблон без деплоя означают только подготовленную инфраструктуру.
