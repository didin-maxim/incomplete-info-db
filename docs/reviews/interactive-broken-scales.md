# Интерактивы для задач со сломанными весами

Дата ревизии: 2026-05-19.

Заметка 2026-05-24: часть рекомендаций ниже уже реализована. `kvant-2003-01-three-scales-two-weighings` имеет `faulty_scale_identification`, `lktg-2008-three-balances-one-broken-nine-coins` и малый `lktg-2008-three-balances-one-broken-three-coins` имеют `broken_scale_counterfeit_coin`, `kvant-2019-m2565-one-broken-scale` имеет свой интерактив. Открытыми остаются в основном нижние оценки/шумные варианты, которые не нужно брать как обычную игру без явной adversary-проверки.

Контекст: обычный интерактив `single_counterfeit_weighing` моделирует скрытую фальшивую монету. Для задач ниже это неверная модель: неисправность находится в приборе или в канале наблюдения. В UI и schema это должно быть явно видно через отдельный тип, objective и текст правил.

## Общие правила модели

- Скрытое состояние нельзя сводить к монете, если по условию сломан прибор. Для таких задач состояние содержит неисправные весы, а иногда дополнительно монету, порядок масс или позицию ошибочного показания.
- Действие взвешивания должно включать выбор прибора. Если прибор исправен, ответ детерминирован физическими массами объектов на чашах. Если выбран неисправный прибор, ответ может быть произвольным.
- Режим `random` выбирает скрытое состояние заранее. При использовании неисправного прибора он может выбирать любой допустимый произвольный исход.
- Режим `cheater` не должен "назначать фальшивую монету"; он выбирает наблюдаемый исход, оставляющий максимальное число совместимых скрытых состояний с неисправным прибором.
- Режим `exhaustive` нужен, когда пользователь строит гарантирующую стратегию. Ветка решена только если во всех совместимых состояниях один и тот же требуемый ответ.
- В обычных режимах безопасно показывать счетчик совместимых состояний и историю действий. Полный список состояний лучше показывать только в режиме полного перебора или после финала.

## Проверенные карточки

### `kvant-2003-01-three-scales-two-weighings`

- Уместность: да, это самый простой безопасный интерактив класса.
- Скрытое состояние: одна из трех пар весов `A`, `B`, `C` неисправна.
- Объекты: сами весы являются и приборами, и взвешиваемыми предметами; неисправные весы легче исправных как предмет.
- Действия: выбрать прибор, положить другие весы на левую и правую чаши, получить один из трех исходов.
- Ответ неисправного прибора: произвольный исход при каждом использовании.
- Полный перебор: нужен и мал; состояние всего из трех вариантов, лимит два взвешивания.
- Решение по реализации: добавлен новый тип `faulty_scale_identification`; он не переиспользует модель фальшивой монеты.

### `lktg-2008-three-balances-one-broken-nine-coins`

- Уместность: да, но не как первая реализация.
- Скрытое состояние: фальшивая легкая монета из 9 и одна сломанная пара весов из 3. Цель - найти только монету, не обязательно сломанные весы.
- Объекты: 9 монет; приборы - три разные пары чашечных весов.
- Действия: на каждом шаге выбрать одну пару весов и две группы монет одинакового размера; до 4 взвешиваний.
- Ответ сломанного прибора: произвольный каждый раз. Исправные весы показывают физический исход для одной легкой монеты.
- Полный перебор: нужен для проверки интерактивной стратегии, потому что adversarial-ветки должны сохранять совместимость по паре `(монета, сломанные весы)`.
- Риск сейчас: официальная стратегия использует координаты монет, контрольное третье взвешивание и затем разбор противоречий между приборами. Нужен движок с состояниями `(coin, broken_scale)` и целью `identify_coin`, где ветка считается решенной, если все совместимые состояния имеют одну монету, даже если сломанные весы еще не определены.

### `lktg-2008-broken-balances-ternary-lower-bound`

- Уместность: скорее нет для обычной игры; да для будущего демонстратора нижней оценки.
- Скрытое состояние: монета и неизвестный неисправный прибор, но число приборов и монет параметрическое.
- Действия: произвольные взвешивания на любых весах.
- Ответ шулера: выбирать исход так, чтобы сохранялась большая доля возможных монет.
- Полный перебор: для общего `k` быстро становится не UI-задачей; полезнее специализированный демонстратор adversary-аргумента.

### `kvant-2019-m2565-one-broken-scale`

- Уместность: пока отложить.
- Скрытое состояние: полный порядок разных масс монет и номер одной испорченной пары весов; цель - найти самую тяжелую монету.
- Действия: выбрать одну пару весов и две монеты для сравнения.
- Ответ неисправного прибора: может быть правильным или неправильным произвольно.
- Полный перебор: для фиксированного малого `n` возможен, но исходная задача параметрическая и оптимальная стратегия индуктивная. Нужен отдельный движок турнира сравнений с порядком масс, а не монетный движок.

### `problems-ru-35224-noisy-balance-four-coins`

- Уместность: близко, но это не сломанный прибор среди нескольких весов.
- Скрытое состояние: одна из 4 монет и знак отличия.
- Особенность прибора: равновесие не наблюдается надежно; при равных массах весы произвольно выбирают чашу.
- Вывод: нужен тип `single_counterfeit_unknown_direction` с измененной алфавитной моделью исходов: физическое равновесие совместимо с двумя перекосами, но не с отдельным исходом `balance`.

### `yumt-2014-sensitive-scales-17-coins`

- Уместность: отложить.
- Скрытое состояние: две соседние легкие монеты на цикле.
- Особенность прибора: поломка является дополнительным наблюдаемым исходом с указанием стороны, а не скрытым неисправным прибором.
- Вывод: это отдельный тип с пятью исходами одного взвешивания; не смешивать с `faulty_scale_identification`.

## ТЗ для LKTG

1. Ввести тип `broken_scale_counterfeit_coin` или близкий, с параметрами `coin_count`, `scale_count`, `broken_scale_count: 1`, `counterfeit_weight: lighter`, `max_weighings`, `objective: identify_coin`.
2. Состояния хранить как пары `{ coin, brokenScale }`. Для `9 x 3` это 27 состояний.
3. Исход для исправного прибора считать как в известной легкой монете. Исход для сломанного прибора совместим с любым из трех результатов.
4. В `random` скрытая пара фиксируется заранее; при взвешивании на сломанных весах результат выбирается случайно.
5. В `cheater` выбирать исход с максимальным числом совместимых пар. Финальный ответ принимать, если названная монета совпадает с единственной монетой во всех оставшихся парах.
6. В `exhaustive` ветка `solved`, если множество оставшихся пар имеет одну проекцию на монету; сломанные весы могут оставаться неоднозначными.
7. UI должен показывать две сущности: монеты как объекты и весы как приборы. В истории записывать, какой прибор использован.
8. Не добавлять готовую координатную стратегию в YAML `interactive`; карточка может хранить только параметры модели.
