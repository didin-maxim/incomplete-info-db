# Аудит интерактивов: одна фальшивая монета и близкие варианты

Дата аудита: 2026-05-25.

Область: карточки с `interactive.type` = `single_counterfeit_weighing`, `single_counterfeit_unknown_direction`, `multiple_light_find_one`. Аудит аналитический: карточки и код не менялись.

Счёт действий грубый: одна монета, положенная на чашу, считается как 1 перетаскивание; кнопка `Взвесить` - 1 клик; финальный ответ обычно 2 действия (`Указать...` + клик по монете), для ответа со знаком еще 1 выбор в селекте, если текущий знак не тот. Для заранее заданных таблиц один заполненный текстовый input считается как 1 действие, хотя реально это много набора.

Важное общее UX-наблюдение: в адаптивных весовых интерактивах режим статусов по умолчанию `ручной`. В нем клик по монете меняет цветовой статус, а не кладет монету на чашу. Раскладывать монеты можно перетаскиванием, либо сначала переключить `Статусы -> авто`, после чего клик циклически двигает монету `запас -> левая -> правая -> запас`. Это функционально, но легко спутать с основной механикой.

## Общие UX и Технические Замечания

| Тема | Наблюдение | Риск | Предложение |
|---|---|---|---|
| Режимы `challenge/sandbox` у adaptive single-counterfeit | `lighter-25` и `problems-ru-34945` задают `modes: ["challenge", "sandbox"]`, но нормализатор для adaptive принимает только `random/cheater/exhaustive`; в результате фактически остается `random`. | Пользователь и ревью-док ожидают challenge/sandbox, а UI их не показывает. | Либо поддержать эти алиасы, либо заменить YAML-режимы на реальные. |
| Клик по монете | При статусах `ручной`/`с проверкой` клик меняет цветовую пометку, а не кладет монету на чашу. | Новичок кликает монеты и видит смену цветов вместо перемещения. | Явно подписать: “для раскладки перетаскивайте монеты или включите `Статусы: авто`”. |
| `Ответить знаком` и селект знака | В DOM они присутствуют и в некоторых проверках выглядят видимыми даже там, где цель не sign-only. | Лишние элементы могут сбивать, если реально видимы в браузере/на разных layout. | Проверить `hidden` для `data-answer-direction-wrap` и `data-answer-sign-only` на всех целях. |
| Цвета статусов | Зеленый/желтый/красный понятны; blue/orange/purple для lighter/heavier/both понятны только по легенде. | Без чтения легенды пользователь не поймет, что синий = “может быть легче”, оранжевый = “может быть тяжелее”. | Оставить легенду всегда видимой; в тяжелых unknown-direction задачах добавить короткий status-текст после первого взвешивания. |
| Typed-mass labels | В `five-silver-four-gold...` labels заданы как `silver/gold`, а заголовок нормализован как “фальшивая легче”, хотя gold-фальшивка тяжелее. | Математическая модель работает, но интерфейс терминологически врет. | Русифицировать labels и заменить heading на “знак зависит от металла”. |
| Большие объекты | 25/27 терпимо, 99/100 нет. | Вручную прохождение превращается в механику перетаскивания, а не решение. | Для 99/100 использовать малые companion-карточки: sign-only на 9 монетах, limited-use на 19 монетах. |

## Честные Предупреждения Для Тяжёлых Режимов
