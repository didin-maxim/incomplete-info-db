# Интерактив: `matprazdnik-2025-eighteen-coins-rotated-tray`

Дата: 2026-05-22.

## Статус

Интерактив не добавлен. Нужен перенос существенного рисунка из официальной брошюры в самодостаточную модель карточки.

Главный blocker: в YAML сейчас есть только текст "монеты разложены по известному рисунку" и словесная идея решения. Нет списка 18 позиций по кругу, базовой раскладки весов на этих позициях и отмеченных групп из официального рисунка. Без этих данных любой интерактив будет либо раскрывать непроверенную реконструкцию, либо подменять исходную задачу новой задачей с другим рисунком.

## Восстановленная модель

- Скрытое состояние: неизвестный поворот известной круговой раскладки 18 монет. В раскладке по две монеты каждого веса от 1 до 9 граммов.
- Действия пользователя: выбрать подмножества видимых позиций на левую и правую чаши и выполнить до двух взвешиваний. Второе взвешивание может зависеть от первого исхода.
- Наблюдение: один из трех исходов чашечных весов - левая легче, равновесие, правая легче. Числовой вес не сообщается.
- Цель: восстановить вес каждой видимой позиции после поворота подноса.
- Роль поворота: поворот действует на известную круговую раскладку как циклическая симметрия. Пользователь видит позиции на подносе, но не знает, какая позиция исходного рисунка попала в выбранную ориентацию.
- Роль симметрии в стратегии: первое взвешивание должно разбить возможные повороты на три класса, соответствующие исходам весов. По текущей стратегии карточки эти классы связаны с тройками весов 1,4,7; 2,5,8; 3,6,9. Второе взвешивание закрепляет оставшуюся циклическую неопределенность внутри выбранного класса.
- Лимит ходов: два взвешивания.

## Почему текущие движки не подходят

- `single_counterfeit_weighing` и родственные движки ищут фальшивую монету; здесь все веса разные и нужно восстановить всю раскладку.
- `numeric_linear_signature` работает с числовыми показаниями или числовой подписью. В этой задаче наблюдение тернарное, а скрытое состояние - поворот целой раскладки.
- `balanced_weight_signature_protocol` кодирует объекты через заранее заданные подписи, но не моделирует циклическое действие рисунка и цель "восстановить все веса после поворота".
- `finite_binary_state_protocol` не подходит из-за трех исходов взвешивания.

## Минимальный честный движок после снятия blocker

Рабочее имя: `rotated_tray_balance_protocol`.

Минимальный YAML-контракт:

```yaml
interactive:
  type: rotated_tray_balance_protocol
  position_count: 18
  base_weights: [ ... 18 чисел по кругу из официального рисунка ... ]
  rotation_group: cyclic
  max_weighings: 2
  objective: identify_all_weights_after_rotation
  modes: [random, cheater, exhaustive, sandbox]
```

Если официальный рисунок использует именованные позиции или отмеченные группы, нужны дополнительные поля:

```yaml
  position_labels: [A, B, C, ...]
  marked_groups:
    first_left: [...]
    first_right: [...]
```

Эти группы не должны быть обязательной готовой стратегией. Они нужны только если их нельзя восстановить из самодостаточной схемы рисунка и они являются частью условия/официального чертежа.

## Логика движка

1. Построить все разные скрытые состояния как повороты `base_weights`. Если два поворота дают одинаковую карту весов из-за повторов, слить их в один наблюдательно неразличимый случай.
2. Для выбранного взвешивания вычислять знак разности сумм на чашах в каждом совместимом состоянии.
3. В режиме `random` выбрать один скрытый поворот и отвечать честно.
4. В режиме `cheater` хранить множество совместимых поворотов и выбирать исход, оставляющий максимальное число состояний.
5. В режиме `exhaustive` после каждого выбранного взвешивания показывать три ветви с количеством оставшихся поворотов, но не раскрывать карту весов до финального ответа.
6. Финальный ответ принимать только если для каждой видимой позиции выбранный пользователем вес одинаков во всех оставшихся совместимых состояниях.

## UI-сценарии для визуальной проверки

- Старт: показан круг из 18 позиций без весов, две чаши, счетчик "осталось возможных поворотов"; нет готового первого взвешивания.
- Режим `random`: пользователь кладет позиции на чаши, получает один тернарный исход, после двух взвешиваний заполняет веса 1..9 по две копии и получает проверку.
- Режим `cheater`: после каждого взвешивания счетчик совместимых поворотов не возрастает, исход выбирается из непустых ветвей, скрытая раскладка не раскрывается.
- Режим `exhaustive`: для каждого хода видны три ветви с размерами множеств состояний; ветвь считается решенной только когда все позиции имеют вынужденные веса.
- Мобильный экран: круг из 18 позиций не должен перекрывать чаши и историю; подписи позиций остаются читаемыми.

## Что нужно до реализации

1. Перенести официальный рисунок в карточку как `base_weights` по часовой стрелке или как самодостаточную схему с 18 позициями.
2. Сверить, сколько разных поворотов реально нужно различать: 18, 9 или меньше после отождествления одинаковых весовых карт.
3. Проверить официальные два взвешивания на этой модели прямым перебором всех поворотов.
4. Только после этого добавлять `interactive` и новый узкий renderer.
