# Roadmap сильных интерактивов

Дата: 2026-05-25.

Обновление 2026-05-25: `problems-ru-65817-six-coins-digital-scale-unknown-weights` разобрана отдельно. Не реализовывать ее через `numeric_linear_signature`: скрытое состояние имеет вид `(номер фальшивой монеты, g, f)` с двумя непрерывными массами, а решенная ветка требует проверки линейной совместимости по всем допустимым `g,f`. Нужен будущий тип `numeric_weight_calibration`; см. `docs/reviews/interactive-numeric-calibration-design.md`.

Правило этой очереди: не брать кликалки, пошаговые показы готового решения и большие
таблицы без самостоятельного хода пользователя. Сильный интерактив требует, чтобы
пользователь предъявил вопрос, взвешивание, код, дерево, сертификат или финальный
ответ, а проверка шла по скрытому состоянию, adversary-режиму или полному перебору.

Использованы `interactive-queue-quality-review.md`, `interactive-next-candidates.md`,
`interactive-status.md`, текущие YAML и свежие аудиты 2026-05-25.
Отдельно просмотрены карточки, появившиеся или измененные после отчета
2026-05-24 16:18: среди них новые Квантландия, Math Muggles, CEMC/Calgary и
Khovanova-кандидаты; сильной ближайшей реализации без риска weak demo среди них
не найдено, кроме возможного малого антицепного режима для уже интерактивного
`kvantland-detective-70-witness-criminal`.

## Сразу убрать из "сделать"

Эти карточки или их малые родственники уже покрыты интерактивом, поэтому не должны
попадать в новую очередь реализации:

- `tokarev-expert-judge-six-weights-two-weighings`: в YAML уже есть
  `interactive.type: expert_judge_certificate`, режимы `sandbox`, `exhaustive`.
- `knop-expert-judge-one-weighing-one-weight`: уже есть тот же
  `expert_judge_certificate`.
- `five-silver-four-gold-light-heavy-2-weighings`: уже есть интерактив; нужен только
  UI-текст про знак, зависящий от металла, но не новая реализация.
- `problems-ru-32820-sign-only-two-weighings`: интерактив уже есть, но большой
  98-100-монетный UI слаб по действиям; не ставить как новый кандидат, лучше
  отдельно завести малый companion на 9 монет.
- `kvantland-detective-70-witness-criminal`: уже есть полный интерактив; новая
  задача здесь не полный режим, а малый ручной вариант 6 человек / 4 дня.
- `israelmath-5781-bilbo-three-diamond-piles-safe-pile` и
  `mccme-2016-three-piles-one-genuine-pile`: уже есть `safe_pile_balance_certificate`;
  сильной новой работой может быть только малый вариант 3/5/7, если он будет
  отдельным режимом/карточкой.
- `rmo-2002-three-consecutive-light-weights`, `usamts-2011-zoltar-fourteen-coins-real-coin`,
  `prisoners-hats-parity-line`, `wise-men-6-hidden-hat-number-parity`,
  `wise-men-6-32-colors-one-bit`, `wise-men-6-four-colors-permutation-parity`:
  уже имеют интерактив; часть из них требует предупреждений или подписи
  demonstration/trainer, но не входит в очередь "сделать".
- Малые закрытия крупных задач: `balanced-subset-8-three-questions`,
  `xor-8-coins-one-flip`, `prisoners-10-boxes-cycle-strategy`,
  `three-letter-erasure-4-bit-code`, `twenty-one-card-trick`,
  `calendar-card-binary-trick`, `fitch-cheney-five-card-trick`,
  `password-feedback-permutation-variant`.

Малый случай для UKMT сохраняет идею исходной задачи: исходная карточка про то, что
иногда достаточно найти монету без знака. Уменьшение с 42 до 6 не меняет скрытую
модель и цель, но делает ручное дерево обозримым.

Малый случай для Емельянова сохраняет идею "эксперт убеждает судью": масштаб 100
монет не важен для первого UI, важна публичная проверяемость пары и знака после
двух результатов.

## Невзвешивательные выводы

- Эпистемические задачи почти всегда рискуют стать "фильтром миров". Брать их в
  strong-очередь можно только если пользователь сам предъявляет публичную фразу,
  вопрос или таблицу, а не просто нажимает "следующий раунд".
- Колпаки и фокусы уже имеют сильные малые представители: parity-line, hidden
  number, `xor-8`, MCCME five-number cards. Новые большие версии без нового действия
  будут дублями.
- Карточные фокусы с готовым алгоритмом (`twenty-one`, Fitch Cheney, calendar cards)
  полезны как demonstration, но не должны поднимать приоритет новых exercise.

## Задачи для high reasoning агентов

1. Спроектировать и реализовать `property_verification_balance` для
   `four-guineas-exactly-two-counterfeits-verification`: формальная модель состояний,
   критерий принятия дерева, режимы `random/cheater/exhaustive/sandbox`, UX финального
   ответа "свойство верно/не верно".
2. Спроектировать малый `identify_coin_only_unknown_direction` на 6 монетах для
   UKMT: доказать, что модель корректно склеивает два знака одной монеты, и дать
   exhaustive-checker для дерева до 3 взвешиваний.
3. Спроектировать `noisy_balance_unknown_direction`: двухисходная надежная модель
   без trustworthy balance, полный перебор 8 состояний, adversary-режим и текстовое
   предупреждение, чем это отличается от обычных весов.
4. Спроектировать `numeric_weight_calibration` для `problems-ru-65817`: символические
   линейные формы по неизвестным массам, критерий одинакового номера фальшивки для
   всех совместимых масс, минимальный UX без ручной алгебры.
5. Спроектировать малый `expert_judge_two_equal_counterfeits_certificate` для
   Емельянова: состояние `(пара, знак)`, роли эксперт/судья, проверка вынужденности
   пары и знака после двух публичных взвешиваний.
6. Отдельно, не смешивая с реализацией новых задач, пройти YAML-метаданные
   существующих интерактивов: явно отделить `exercise` от `demonstration`, добавить
   `estimated_user_actions` и предупреждения для heavy `exhaustive`.
