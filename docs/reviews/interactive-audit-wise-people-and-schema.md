# Аудит интерактивов: мудрецы, колпаки, заключенные и схема классификации

Дата: 2026-05-25.

Задача аудита: проверить интерактивы про мудрецов, колпаки, публичные или последовательные ответы и близкие prisoner-протоколы; отдельно сформулировать общую шкалу для различения настоящих упражнений и демонстраций. Массовые YAML-правки не вносились.

## Критерий

Рабочее правило для фильтра `С интерактивом`: если пользователь должен предъявить ответ, ход, стратегию, таблицу или сертификат, а viewer проверяет это на скрытом состоянии или полном наборе случаев, это `exercise`. Если UI только показывает уже известный протокол, пошаговую индукцию, готовую таблицу или совместимые состояния без содержательного выбора пользователя, это `demonstration` и должно быть явно подписано. Слабые интерактивы допустимы в базе, но не должны выглядеть как сильные упражнения.

## Wise people без интерактива

`blue-eyed-islanders`, `muddy-children-common-knowledge` и `three-wise-men-hats` сейчас не имеют поля `interactive`, поэтому не попадают в фильтр `С интерактивом`. Это правильное состояние. Для них возможен только явно подписанный demonstrator индукции/общего знания; выдавать их как упражнение без проверяемого действия пользователя не стоит.

Также без интерактива остаются более крупные исходники, для которых уже сделаны малые честные версии: `problems-ru-115987-thousand-wise-men-hidden-hat-number`, `problems-ru-64616-eleven-wise-men-1000-colors-one-bit`, `problems-ru-67032-300-wise-men-25-colors-permutation-parity`, `prisoners-100-boxes-cycle-strategy`. Их не нужно дублировать полным масштабом без новой UX-цели.

## Фильтр `С интерактивом`

Текущая схема уже содержит `interactive.presentation` со значениями `exercise`, `demonstration`, `review_only`; отсутствие `presentation` означает exercise. В данных на момент аудита: 93 карточки с `interactive`, из них 2 явно `presentation: demonstration` (`calgary-jmc-2021-b3-password-feedback`, `spb-primary-2023-seven-coins-two-weighing-results`) и 0 `review_only`.

Важный риск: текущая логика `hasInteractive` исключает только `review_only`, поэтому `presentation: demonstration` тоже попадает в кнопку `С интерактивом`. Если пользователь читает эту кнопку как "есть задача, где надо решать", это смешивает упражнения и демонстрации. Рекомендация: либо переименовать кнопку в более широкое `Есть интерактивный блок`, либо добавить отдельные фильтры/счетчики:

- `С упражнением`: `interactive.presentation` отсутствует или равно `exercise`.
- `Демонстрации`: `interactive.presentation == demonstration`.
- `На ревью`: `interactive.presentation == review_only`, не показывать в публичной поверхности.

## Предлагаемые поля YAML

Не внедрять массово без согласования, но будущая структура может быть такой:

```yaml
interactive:
  type: prisoners_hats_parity_line
  presentation: exercise
  interactive_strength: strong
  estimated_user_actions: 7
  mode_action_estimates:
    random:
      min: 7
      typical: 7
      max: 9
    guided:
      typical: 1
      nature: demonstration
    exhaustive:
      typical: 1
      nature: aggregate_check
  visual_legend_needed: true
  heavy_interactive_warning: false
```

Предлагаемая шкала `interactive_strength`:

- `strong`: пользователь делает содержательный ход/ответ/стратегию, hidden state не раскрыт, viewer проверяет результат.
- `weak`: есть клики и скрытое состояние, но существенная часть решения уже зашита или подсказывается UI.
- `demonstration`: интерактивно показан готовый разбор, без проверяемого самостоятельного решения.
- `remove`: интерактивный блок не добавляет полезного действия и не является хорошей демонстрацией.

`estimated_user_actions`: одно число для типичного успешного прохождения основного режима. Для тяжелых пошаговых протоколов лучше считать проверяемые действия, а не каждый optional reset/select.

`mode_action_estimates`: словарь по режимам. Значение может быть числом или объектом `{min, typical, max, nature}`. Поле `nature` полезно для режимов `guided`, `exhaustive`, `cheater`, потому что действие в них может быть не упражнением, а демонстрацией или стресс-проверкой.

`visual_legend_needed`: `true`, если без легенды неочевидны цвета, маски `?`, роли подсветки, опасные плашки, стрелки/циклы, скрытые и публичные состояния.

`heavy_interactive_warning`: `true`, если типичный путь требует много действий, exhaustive дорогой, или UI может выглядеть как полная игра вместо учебного малого случая. Для текущего пакета кандидат на `true` - `wise-men-6-hidden-hat-number-parity` из-за 6 последовательных ответов с проверкой и переходом.

## Срочные правки по всем интерактивам

1. Развести в публичной навигации exercise и demonstration. Сейчас две явные демонстрации попадают в `С интерактивом`; это нормально только если кнопка понимается широко, но плохо для поиска задач "где надо решить".
2. Добавить минимальные метаданные силы и действий хотя бы для новых интерактивов: `interactive_strength`, `estimated_user_actions`, `mode_action_estimates`. Это снизит риск повторных споров про слабые демонстрационные блоки.
3. Не добавлять `blue-eyed-islanders`, `muddy-children-common-knowledge`, `three-wise-men-hats`, `sum-product-two-numbers`, `cheryls-birthday-sasmo` как exercise без нового проверяемого действия. Если появятся, только как `presentation: demonstration`.
4. Для слабых протоколов, где UI ведет пользователя за руку (`prisoners-10-boxes-cycle-strategy`, guided-режимы колпаков), явно помечать режимы как demonstration/guided, чтобы они не повышали оценку всей карточки.
5. Приоритет следующей разработки из существующих review-доков остается у сильных verifier-интерактивов: `tokarev-expert-judge-six-weights-two-weighings`, `emelyanov-expert-judge-two-counterfeits-two-weighings`, затем `four-guineas-exactly-two-counterfeits-verification` и `five-silver-four-gold-light-heavy-2-weighings`.
6. Для визуально плотных интерактивов добавить короткие легенды на уровне UI или метаданных: что значит `?`, какие элементы являются публичными ответами, какие раскрываются только после проверки, что показывает exhaustive.

## Итог

В пакете нет явной утечки скрытой информации в текущих сильных интерактивах про мудрецов и колпаки: собственный колпак/номер, спрятанный номер и полная раскладка закрыты до проверки. Основной системный риск не в этих пяти карточках, а в смешении `exercise` и `demonstration` под одной кнопкой `С интерактивом` и в отсутствии машинно читаемой силы интерактива.
