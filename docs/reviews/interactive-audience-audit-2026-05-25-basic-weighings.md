# Аудит базовых весовых интерактивов

Дата: 2026-05-25.

Зона аудита: `single_counterfeit_*`, `noisy_balance_unknown_direction`, `paid_weighing_find_genuine` и близкие классические тренажеры из списка задания. Это аудит глазами школьника-решателя: насколько интерактив помогает придумать или проверить решение, не выдает ли готовую идею слишком рано, виден ли объем действий и какие режимы действительно учебные.

Читал: `README.md`, `docs/AGENT_FIELD_GUIDE.md`, `docs/AI_CARD_RULES.md`, `docs/INTERACTIVE_ENGINE_GUIDE.md`, текущие YAML карточек, `docs/reviews/interactive-simple-mode-rules.md`, фрагменты `tools/build_viewer.py` для `single_counterfeit`, `noisy_balance` и `paid_weighing`, начало `viewer/weighing_cheater.js` для модели скрытых состояний и статусов.

Проверка покрытия:

- Целевые 26 id найдены.
- Скриптовый проход по YAML нашел 25 интерактивов типов `single_counterfeit_*` / `noisy_balance_unknown_direction` / `paid_weighing_find_genuine`; все они либо входят в список, либо являются соседним `light-coin-limited-two-uses-preassigned-weighings`.
- `rg -n 'single_counterfeit_|noisy_balance_unknown_direction|paid_weighing_find_genuine' data\problems` подтвердил тот же набор; из близких классических вне списка найден только `light-coin-limited-two-uses-preassigned-weighings`, уже снятый в `review_only/remove`.
- Дополнительно в списке задания есть два близких, но не попадающих в этот rg-класс: `counterfeit-stack-one-weighing` (`numeric_linear_signature`) и `sixteen-coins-zero-one-two-fakes-sign` (`zero_one_two_counterfeit_sign`).

## Главные выводы

1. Лучший первый маршрут для школьника: `heavier-9-coins-2-weighings` -> `lighter-8-coins-optional-2-weighings` -> `three-coins-unknown-sign-two-weighings` -> малые identify-only/noisy/paid варианты. Большие 25/27/100-монетные карточки не должны быть первым экраном.
2. `random` и `cheater` полезны в адаптивных малых задачах, где ученик сам выбирает взвешивание и ответ. Для заранее заданных таблиц они либо не применяются, либо были правильно заменены на `sandbox`/`exhaustive`.
3. `exhaustive` почти всегда является сертификатом гарантии, а не обычной школьной игрой. Он хорош для 4, 8, 9 состояний; для 12/13/14/27 и erasure-кодов нужен warning, агрегаты или явное "проверяем готовый план".
4. `sandbox` полезен как лаборатория для неадаптивного кода, но сам по себе не доказывает решение школьнику. В preset-карточках он должен сопровождаться задачей "построй таблицу" или честной маркировкой demonstration/certificate.
5. Несколько хороших интерактивов старого слоя не имеют `presentation`, `interactive_strength`, `estimated_user_actions`: особенно 13-монетные, `three-coins`, `kvant-2003`, `moebius`, `counterfeit-12`. Из-за этого объем работы и режимы хуже обозримы, чем в новых карточках.
6. Снятия в `review_only/remove` выглядят оправданными для `lighter-25`, `nrich-spot-the-fake`, `problems-ru-32820` и соседнего `light-coin-limited-two-uses...`: публичный режим там либо тяжелый дубль, либо не проверяет главный смысл задачи.
7. Erasure/reserve-планы Кнопа и preassigned-версии 12/13 монет сейчас сильнее для техаудита, чем для школьника: готовая таблица часто является преждевременной подсказкой.
8. Самые удачные public-сильные случаи в текущем наборе: `heavier-9-coins-2-weighings`, `lighter-8-coins-optional-2-weighings`, `five-silver-four-gold-light-heavy-2-weighings`, `problems-ru-35224-noisy-balance-four-coins`, `problems-ru-65055-paid-weighings-genuine-coin`, `ukmt-open-ended-2013-six-coins-identify-only-trainer`.

## Рекомендации по режимам

| Режим | Вердикт для школьника |
|---|---|
| `random` | Хорош для первой тренировки одной ветки, но не доказывает гарантию. Особенно полезен в `heavier-9`, `lighter-8`, `three-coins`, `paid`, `noisy`, UKMT trainer. |
| `cheater` | Полезен, когда задача требует гарантии: ученик видит худшую совместимую ветку. Для малых адаптивных весов это лучший учебный стресс-тест. |
| `exhaustive` | Нужен как сертификат полного дерева. Учебен только при малом размере или хорошей агрегации; иначе это техаудит. |
