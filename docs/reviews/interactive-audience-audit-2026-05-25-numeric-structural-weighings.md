- Не хватает обозримости действий: из 34 проверенных id явные `estimated_user_actions` есть только у `rmo-2002-three-consecutive-light-weights`, `kvantik-2021-three-by-three-fake-line-one-weighing`, `utyum-2010-seventeen-coins-parity-test`, `spb-primary-2023-seven-coins-two-weighing-results`. Для остальных режимов школьнику труднее понять, сколько осмысленных шагов ожидается.
- `safe_pile_balance_certificate` математически хорош, но текущие 17/21/27 объектов превращают одноходовую идею в большой визуальный сертификат. Это лучший кандидат на малый учебный вариант 3/5/7.
- `exhaustive` полезен школьнику только на малых пространствах вроде 6-20 состояний. Для 63/70/128/130/3432/24310 состояний это в первую очередь редакторская проверка, и UI должен говорить об этом прямо.
- Большие числовые подписи (`thirteen-labeled...`, `rmo-2002...`, `problems-ru-78572...`) не надо снимать, но им нужны warning, микрохелп и/или малый входной вариант, чтобы не стать вводом огромной таблицы.
- Структурные раскладки помогают, когда геометрия сохранена: круг, ряд с границей, 3x3 сетка, пары и группы. Если заменить их плоскими списками, часть решения исчезает из поля зрения.
- `random` обычно полезен как одиночная попытка, `cheater` - как учебный adversary/фильтр совместимых состояний, а `exhaustive` - как проверка стратегии. Для больших задач это надо различать в подписи режима.
- `spb-primary-2023-seven-coins-two-weighing-results` правильно оставлен демонстрацией: там уже даны результаты, и честная активность - пошаговое пересечение кандидатов, не построение стратегии.
