# Как предлагать правки

Сейчас база находится в стадии чернового проектирования. Особенно полезны три
типа замечаний:

1. Математические: условие, стратегия, доказательство оптимальности, сложность.
2. Навигационные: фрагменты, профильные поля, теги, родственные связи.
3. Архитектурные: где схема мешает поддерживать разные классы задач.

## Базовые правила

- Каждая карточка должна явно отделять условие, идеи, стратегии и нижние оценки.
- Стратегия в `strategies[]` должна быть полной: по ней можно воспроизвести
  действия участника и проверить, почему она всегда достигает цели.
- Если есть только идея стратегии, но нет полного доказательства, оставьте ее в
  `ideas[]`, а `strategies[]` не заполняйте.
- Доказательство невозможности или оптимальности кладется в
  `impossibility_proofs[]` или в стратегию как отдельный раздел, если оно
  неотделимо от стратегии.
- Не добавляйте родственную связь только по общей теме. Нужен общий механизм:
  кодирование состояний, индукция по публичным объявлениям, партиционирование,
  симметрийная стратегия, информационная нижняя оценка.
- Для задач со взвешиваниями обязательно заполняйте `weighing_profile`, если
  известны число объектов и число взвешиваний.
- Пользовательские тексты пишутся на русском языке. Латиница допустима для
  id, URL, формул, имен источников и стандартных английских названий.
- Источник истины - `data/`. Viewer, docs и SQLite-индекс пересобираются.

## Формат файлов

Файлы `*.yaml` в `data/` являются JSON-совместимым YAML:

- валидный JSON;
- двойные кавычки;
- без YAML-якорей, `|`, trailing commas и комментариев внутри данных;
- UTF-8 без BOM;
- LaTeX backslash экранируется как `\\(`, `\\le`, `\\binom`.

## Минимальная проверка после правок

```powershell
python tools\validate.py
python tools\check_links.py
python tools\audit_rules.py
python tools\build_viewer.py
```
